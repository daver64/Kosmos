# Kosmos 0.38

- KosmosCAD: textured view. Z now cycles the active view through wireframe, solid and textured; textured shows each material's image (PNG, JPG or Orbiter DDS), with plain colour for materials that have none (or a checker, from the UV editor panel). View > Render image (PNG)... saves the textured perspective view without the grid and gizmos.
- KosmosCAD: a Blender-style UV editor (U). The left half shows the material's image with the UV wireframe of the selected faces (or objects) over it; drag to move, rotate (R) or scale (S) the mapping, click or Ctrl+drag to pick UV points, flip, rotate 90, fit to 0..1, or type exact numbers. The part updates live in the textured perspective view, and each drag is one undo step.
- KosmosCAD: the views now fill the whole window. The scene list and the properties are floating tool windows (Scene F2, Properties F3, or the toolbar and View menu) that you can drag anywhere.
- KosmosCAD: the views are anti-aliased (4x multisampling) and the perspective depth range is tighter, which removes the speckle and z-fighting on dense meshes.
- KosmosCAD: a Modify menu holds the modelling tools (extrude, inset, mirror, booleans, sketch and so on), the window layout is remembered between sessions, and the status bar lists the main keys on start.
- KosmosCAD: the UV editor draws the other faces of the object faintly in Face mode, with tick boxes to hide the UV points or the faint faces.
- KosmosCAD: View > Render... opens a window with the rendered image and Save as PNG, Copy and Render again buttons.
- KosmosCAD: opens and imports meshes: Orbiter .msh (textures found in the Orbiter Textures folders), glTF/GLB and OBJ. File > Export can write GLB as well as OBJ.
- KosmosCAD can edit sim parts like Blender does: the part editor and the base editor have a Mesh editor choice (Blender or KosmosCAD, `mesh-editor` in settings). KosmosCAD opens the part with `--edit-mesh FILE`, Ctrl+S (Send to Kosmos) rewrites the .glb/.obj and the sim reloads it, and closing resumes the sim. Blender stays supported and is the more capable editor; KosmosCAD cannot write .gltf parts.
- KosmosCAD: materials can now carry a normal map, a metallic-roughness (specular) map, metallic and roughness values and an emissive colour, with Browse buttons for the images. The textured view shows them. They are saved in .kmodel and GLB (all of them) and in OBJ+MTL (colour, normal map as map_Bump, and Pm, Pr, Ke; the spec map is GLB-only), and imported again from glTF and MTL.
- simlib: the OBJ loader reads the MTL keys Pm (metallic), Pr (roughness) and Ke (emissive) and shades such materials as PBR, so shiny metal and glowing windows work in OBJ parts. Needs the matching simlib build.
- KosmosCAD: File > Export GLB... (with materials and textures embedded), and a new tutorial on the website: a low-poly cylinder with a colour texture.
- OBJ parts are now named by their `o` object name (as Blender and other 3D tools write it) instead of by material; files without `o` lines behave as before, `g` is ignored, and animations and visibility rules match either the part name or the material name. KosmosCAD writes `o` lines, and vessel/vent/crew tags and virtual-cockpit MFD screens are found by the same names. Needs the matching simlib update.
- The MFD Operations Manual on the website now has a screenshot of each display and of the Transfer and OrbitComp walkthroughs (`scripts/make-mfd-shots.sh` takes them).
- The Linux and Windows build scripts now delete earlier `kosmos-beta-*` packages before a default build, so only the release being built is left in `build/package`.
- Time acceleration above 4x is smoother: the simulation now advances by a smoothed frame time, so millisecond timer rounding and the odd slow frame no longer show up as jerky motion at 1000x and above.
