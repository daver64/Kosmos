# Kosmos: Beyond the Horizon

The reel is assembled from frames rendered by Kosmos, an original procedural
score and a separate effects stem. It uses FFmpeg, FFprobe, Python 3, NumPy and
SciPy; build `kosmos` first. The Linux workflow below uses SDL's off-screen
driver and limits rendering and encoding to four threads. No desktop window
or player configuration is needed.

```sh
cmake --build build --target kosmos -j4
python3 scripts/showreel/render.py --preview --output build/showreel
python3 scripts/showreel/render.py --final --output build/showreel
```

The preview is 640x360 at 10 fps; the master is 1920x1080 at 30 fps. Both are
90-second H.264 MP4s with stereo 48 kHz AAC. The output directory also contains
individual scene clips, separate WAV score and effects stems, and asset credits.
The renderer refuses to overwrite an existing output; use a fresh `--output`
directory after an interrupted run. `--binary` selects another Kosmos build.
For quick composition checks, use `--survey`, optionally with
`--only kennedy-wide,moon,iss`.

Edit [timeline.json](timeline.json) to change shots, titles, durations or camera
keys. Each external camera key specifies presentation time in seconds, yaw and
pitch in degrees, distance in metres and field of view in degrees. The camera
tracks the active ship in the local orbital frame and eases between keys; it is
not a free-camera spline or a general mission editor. Set-at commands and
warm-up use the simulator clock, so allow for warm-up when timing an event.

The opt-in capture interface is:

```sh
kosmos --capture-frames DIR FPS COUNT WIDTH HEIGHT \
       --capture-warmup FRAMES --capture-camera camera.json [other options]
```

It saves numbered PNGs, fails rather than overwriting them, and advances the
presentation clock by one frame at a time. Warm-up frames run the simulation
but are not saved. Quantum transition frames are captured as part of the same
timeline. Unlike the normal real-time video recorder, this mode does not record
live audio; the score and effects are mixed afterwards. Simulation warp remains
separate from presentation time. Asynchronous textures, terrain and some
wall-clock effects mean output is not guaranteed to be bit-identical.

## What is shown

The edit moves from the Saturn V on the Kennedy pad and its actual simulated
liftoff to Earth orbit and a live cockpit MFD, then to the Moon and a landed
Mars spacecraft. The interstellar section uses the existing galaxy map and
real quantum-jump transition to Tau Ceti. Argo is no longer an installed addon,
so the quantum-capable Shuttle-AQ is used instead. The jump is invoked by
`--test-jump`, rather than depicting a flown portal entry. The final flight
shows a Deltaglider using RCS near the ISS; it does not claim a docking. Shots
are edited together, not a single continuous flight; no stage separation or
lunar/Martian descent is depicted.

## Credits and distribution

The music is generated by [score.py](score.py); it does not use a film score
or recording. The effects stem includes `liftoff.wav` and `main_engines.wav`
from XRSound 3.0, copyright Douglas Beachy, MIT licensed; the remaining effects
are synthesised. The XRSound notice is embedded in the MP4 metadata and copied
with the output. Simulator models and imagery have their own credits and
licences; the renderer copies the relevant credit files and the Ares notice
beside the video. Include those notices when distributing it and check any
optional local scenery packs' individual licences before publication.
