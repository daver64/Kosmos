# Asset provenance: work in progress

This is an inventory of findings, not a clearance of the repository, its
history, packages, SDK, screenshots or video. Public distribution requires
an asset-by-asset review of the exact files and applicable conditions.
Availability on a website, a permissive code licence, or use of public source
imagery does not by itself establish the rights to redistribute a derivative.

This is not an exhaustive list. In particular, also review other add-ons,
base props, terrain, SDK content, fonts, screenshots and untracked files that
the packaging process can copy. `simlib_add_package` copies directories from
the working tree, not the Git index: ignored PNG model textures and other
local files may therefore enter an archive even though a clean checkout does
not contain them. Inspect the actual archives and their asset references;
do not infer their contents from `git ls-files`. Removing files from the current Git index
does not remove them from previous commits. The GitHub `main` and
`old-history` branches were rewritten to remove the identified assets and
superseded texture blobs. Local branches, checkpoint refs, old archives and
server caches can still retain old objects; the rewrite is not a clearance
of other assets or a guarantee of deletion from every copy.

As a concrete example, a name-only comparison of the now-removed 0.51 Linux and
Windows application archives against the current index found respectively
429 and 433 packaged asset paths absent from that index. These are old,
uncleared archives built before the Ariane exclusions, and the counts include
staged removals and generated files as well as ignored local assets.
`scripts/audit-package-files.py` can repeat this comparison for a new build;
it does not compare contents or establish redistribution rights.
