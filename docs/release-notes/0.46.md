# Kosmos 0.46

- Science instruments. A probe or satellite can carry cameras (visual, infrared, ultraviolet), a radar and a spectrometer, declared in `ship.json` under `"instruments"` and each tied to a switchable LOAD. They are not selectable cameras: the new Instruments MFD (INST) renders a second view from the instrument's mount, with slew-limited pointing, a power check, film frames and a shutter that closes when the sun is near the boresight.
- SHOOT saves a full-resolution PNG (a CSV for the spectrometer) to the `instrument-shots/<ship>/` folder of the user directory; GALLERY browses them.
- Voyager carries narrow and wide cameras, IRIS (infrared) and UVS (spectrometer); Luna E3 carries its film camera.
- OrbitComp's Lambert plan now searches how long to wait before burning as well as the flight time, so a transfer to the Moon from an inclined or eccentric orbit no longer prices a burn made right now; TO MAN loads the burn at the right delay.
- KosmosMission, a new GTK mission planner (Linux and Windows): start point, ship and payload, a delta-v budget from the ship's stages, and a list of legs (ascent, Hohmann, plane change, transfers to planets and moons with a porkchop plot, return to the parent). Missions save as scenarios, export as text or CSV, and a leg can be sent to OrbitComp's node in the running game.
- KosmosMission carries payload ships: add any ship, several kinds and counts (a Dragonfly and a dozen probes), at their full mass, and it checks they fit the launcher's payload volumes. Ships declare volumes with `payload_bays` (cylinders or boxes) and their own size with `payload_size` in `ship.json`; the Saturn V, Ariane 5 and Atlas have bays, and the Dragonfly and Luna E3 have sizes. The fit check is conservative. Without a declared volume the mass counts but nothing is checked. Payload stacks: build a 2-3 stage stack (for example Centaur G, Fregat, a probe) with Add to stack / Add stack; it counts as one payload, its mass and size are summed, and its own delta-v can be added to the budget. When you save or start the game, the first unit in each bay is docked to the launcher in the scenario (bays name the launcher port with `"port"`); the rest are listed as not placed. All CVEL launchers now declare payload bays (sizes are estimates), and ships from an add-on's `"ships"` list now appear in the ship list.
- The launcher has a KosmosMission button on the Play page. KosmosMission can now start Kosmos itself (with the mission as the scenario, via `--link`) when you press **Start Kosmos with this mission** or **To game** and no game is running; it then sends the leg once the game answers. The tools that ship with Kosmos (KosmosMission, KosmosMap, KosmosCAD, KosmosAV, ShipEdit) are now allowed to connect without approval; other native addons still need allowing under View > Native addons.
- Direct3D 12 now draws textured, splatted terrain (texture arrays, layer blending, normal maps, macro variation, shadows and fog), matching the OpenGL and Vulkan backends. This is new and has only been compiled, not run on a GPU, in development: report any terrain glitches under `--d3d12`.
- KosmosMission has a **Guide** button and a web-page walk-through of a complete mission: assemble a stack, fly the ascent, then a Lambert or Hohmann leg.
