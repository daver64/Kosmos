# Kosmos 0.25

## KosmosLink protocol 2
- Native addons can read the weather at any place and height (wind, cloud, visibility, temperature, pressure) and set it: a METAR, a preset or back to automatic. Setting it needs the new `world` permission.
- Opt-in events for native addons: pause, warp, scenario, soi, crash, touchdown, weather, ships and a once-a-second tick. Programs only get the ones they subscribe to.
- Native addons can list the ships near the flown one, move any ship to a latitude, longitude and altitude, and remove the ships they spawned.
- Native addons can list airports and bases near a point, with runways, ILS frequencies and navaids.
- The SDK gains the matching C, C++ and Python calls, a weather MFD example, a nearest-runway example and an updated manual and protocol document. Protocol 1 programs keep working.

## KosmosLink protocol 3
- Native addons can show windows (labels, buttons, checkboxes, sliders, text) and notices with the new `ui` permission, and receive the clicks and edits.
- Lockstep: a program with `controls` can make the simulation wait for it each step, with an optional fixed step, for tight autopilots. Time warp stays at 1x while it is on.
- Vessel claims: with the new `vessel` permission a program can own a ship's controls and apply forces and torques to it. The flown ship can be claimed only if the player allows it. A ship's `ship.json` may carry a `module` block naming the addon and its force limits; it does not launch the program.
- 3D drawing with the new `draw3d` permission: named layers of lines, markers, labels, rings and spheres placed by latitude and longitude, body-fixed or ship-local position. They are drawn over the scene and hidden behind the planet and, approximately, behind ships; scenery does not hide them.
- Ping timeout: a protocol 3 program that stops answering is pinged and then dropped; the timeout is set in View > Native addons. Protocol 1 and 2 programs are never timed out.
- A `fire` request (`kl_fire`, with the `spawn` permission) pulls or releases a ship's weapon trigger, so programs can shoot with any ship.
- The SDK gains the matching calls in C, C++ and Python, four new examples (`ui_panel`, `lockstep_hold`, `waypoints3d`, `vessel_hover`), a manual section and a protocol update.


## Ship weapons
- Ships can carry beams, pulses, bolts, volleys and flak: neon streaks with a halo, hot sparks, flashes and explosions where they hit terrain, buildings and ships. Weapons are JSON in `<addon>/weapons/*.json`, mounted from `ship.json` (`weapons`).
- Shots light the scene. At most four weapon lights are used at once (Settings > Weapon lights), sharing the 16 scene light slots.
- Shields: `ship.json` `shield` absorbs weapon hits before the hull, recharges after a quiet spell and flashes in its colour. They do not stop bombs. `/ships/ship[N]/shield` and `health` show the levels.
- Keypad 1 and 7 fire the primary and secondary groups; any ship fires through `/ships/ship[N]/weapons/<group>/fire`, so scripts and scenarios can make ships shoot each other; link programs use the new `fire` request (below). Beams fire as a pulse that flares and fades out, then recharge (2 s by default, set per weapon), with a deep whump and hum; sparkles are volleys of six small, bright shots with a plasma-rifle zap. Four tiers each of beam and sparkle weapons (red, yellow, green, violet, increasing in effect) ship in `field-kit`; the Deltaglider and the Argo are fitted with them and a shield.
- New `--selftest-weapons`, run by `scripts/run-tests.sh`.
