# Kosmos 0.46

- Science instruments. A probe or satellite can carry cameras (visual, infrared, ultraviolet), a radar and a spectrometer, declared in `ship.json` under `"instruments"` and each tied to a switchable LOAD. They are not selectable cameras: the new Instruments MFD (INST) renders a second view from the instrument's mount, with slew-limited pointing, a power check, film frames and a shutter that closes when the sun is near the boresight.
- SHOOT saves a full-resolution PNG (a CSV for the spectrometer) to the `instrument-shots/<ship>/` folder of the user directory; GALLERY browses them.
- Voyager carries narrow and wide cameras, IRIS (infrared) and UVS (spectrometer); Luna E3 carries its film camera.
- OrbitComp's Lambert plan now searches how long to wait before burning as well as the flight time, so a transfer to the Moon from an inclined or eccentric orbit no longer prices a burn made right now; TO MAN loads the burn at the right delay.
- KosmosMission, a new GTK mission planner (Linux and Windows): start point, ship and payload, a delta-v budget from the ship's stages, and a list of legs (ascent, Hohmann, plane change, transfers to planets and moons with a porkchop plot, return to the parent). Missions save as scenarios, export as text or CSV, and a leg can be sent to OrbitComp's node in the running game.
- Direct3D 12 now draws textured, splatted terrain (texture arrays, layer blending, normal maps, macro variation, shadows and fog), matching the OpenGL and Vulkan backends. This is new and has only been compiled, not run on a GPU, in development: report any terrain glitches under `--d3d12`.
